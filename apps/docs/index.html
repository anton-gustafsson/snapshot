A service, not a widget

Remember what a view
looked like.

snapshotService.capture(el, id) turns any DOM element into a stored image, keyed however you want, on whatever backend you want. <snapshot-nav-list> is one thing you can point it at — not a requirement. Use the service on its own and render the result anywhere. 

npm install @snapshot/core
  1. 01

    Capture on the way out

    Call snapshotService.capture(el, id) when the user leaves a view — any element, any framework.

  2. 02

    It's stored, keyed by id

    IndexedDB by default. Swap in your own backend so it follows the user across devices.

  3. 03

    Show it wherever

    snapshotService.get(id) returns the image URL — an <img>, a <snapshot-nav-list> tile, anything.

The service

No UI required.

This is the whole surface area. No component to mount, no framework to adopt — just a function that captures an element and a function that reads it back. 

import { snapshotService } from '@snapshot/core';

// capture anything — a report panel, a canvas, a form preview
const panel = document.querySelector('#quarterly-report');
await snapshotService.capture(panel, 'q3-report');

// read it back wherever — a table cell, an email preview, your own component
const url = await snapshotService.get('q3-report');
thumbnailImg.src = url;

// react to updates from any tab, any origin-mate that shares your storage
snapshotService.subscribe((id, url) => updateThumbnail(id, url));

Storage is pluggable

Ship it as-is for a single-device tool, or point it at your own backend so thumbnails follow the user across machines. 

import { SnapshotService, type SnapshotStorage } from '@snapshot/core';

class ApiSnapshotStorage implements SnapshotStorage {
  async save(id: string, blob: Blob) {
    const body = new FormData();
    body.append('file', blob, `${id}.png`);
    const res = await fetch(`/api/snapshots/${id}`, { method: 'POST', body });
    return (await res.json()).url;
  }
  load(id: string) {
    return fetch(`/api/snapshots/${id}`)
      .then((r) => (r.ok ? r.json().then((j) => j.url) : null));
  }
}

export const snapshotService = new SnapshotService({
  storage: new ApiSnapshotStorage(),
});

Storage recipes

Three common configurations. Live, working versions of all three are in the gallery app — /icon-grid etc. use the default, and /sqlite / /sqlite-only cover the other two end to end.

IndexedDB only (the default)

No storage option needed — this is what you get for free.

import { SnapshotService } from '@snapshot/core';

export const snapshotService = new SnapshotService();
// same as: new SnapshotService({ storage: new IndexedDbSnapshotStorage() })

A real database only, no fallback

Point storage straight at it. Every get() is a real query — no client-side cache in front of it, so a slow backend means a slow (but honest) spinner. 

import { SnapshotService, type SnapshotStorage } from '@snapshot/core';

class SqlSnapshotStorage implements SnapshotStorage {
  async save(id: string, blob: Blob) { /* INSERT/UPSERT, return a displayable URL */ }
  async load(id: string) { /* SELECT, return a displayable URL or null */ }
  async remove(id: string) { /* DELETE */ }
}

export const snapshotService = new SnapshotService({
  storage: new SqlSnapshotStorage(),
});

The gallery's /sqlite-only page is exactly this, with sql.js (real SQLite, compiled to WASM) standing in for the database — see apps/gallery/src/sqlite-storage.ts.

Database + IndexedDB preload (stale-while-revalidate)

Serve an instant cached image from IndexedDB while the slower, authoritative source loads in the background, then swap the tile to the fresh image live — no remount — via SnapshotService.publish(). 

import { SnapshotService, IndexedDbSnapshotStorage, type SnapshotStorage } from '@snapshot/core';

class TieredSnapshotStorage implements SnapshotStorage {
  constructor(
    private fast: SnapshotStorage,   // IndexedDbSnapshotStorage
    private slow: SnapshotStorage,   // your real backend
    private onRevalidate: (id: string, url: string) => void,
  ) {}

  async load(id: string) {
    const cached = await this.fast.load(id);
    void this.revalidate(id, cached); // don't await — return the cache immediately
    return cached;
  }

  private async revalidate(id: string, cached: string | null) {
    const fresh = await this.slow.load(id);
    if (!fresh || fresh === cached) return;
    await this.fast.save(id, await fetch(fresh).then((r) => r.blob()));
    this.onRevalidate(id, fresh); // -> snapshotService.publish(id, fresh)
  }
  // save()/remove() should write through to both tiers — see the gallery for the full version
}

let snapshotService: SnapshotService;
const storage = new TieredSnapshotStorage(
  new IndexedDbSnapshotStorage(),
  new SqlSnapshotStorage(),
  (id, url) => snapshotService.publish(id, url),
);
snapshotService = new SnapshotService({ storage });

Full version — including write-through save()/remove() and the keyPrefix handling this snippet skips — in apps/gallery/src/sqlite-storage.ts (TieredSnapshotStorage), wired up in apps/gallery/src/pages/sqlite.ts.
