snapshot-angular

A thin standalone wrapper around <snapshot-nav-list> and the core service — signal inputs/outputs, zoneless-safe, and two capture helpers built around how Angular's router actually tears views down.

Install

npm install @anton-gustafsson/snapshot-angular
// main.ts — one place to configure the service; nothing binds [snapshotService]
import { provideSnapshot } from '@anton-gustafsson/snapshot-angular';

bootstrapApplication(App, {
  providers: [provideSnapshot({ keyPrefix: 'reports:', encode: { type: 'image/webp', maxEdge: 640 } })],
});
import { SnapshotNavListComponent, injectSnapshotCapture, type NavItem } from '@anton-gustafsson/snapshot-angular';

interface Report { owner: string }

@Component({
  selector: 'app-root',
  imports: [SnapshotNavListComponent],
  template: `
    <ngx-snapshot-nav-list
      [items]="items"
      [variantKey]="theme()"
      (select)="onSelect($event)"
      (edit)="onEdit($event)" />
  `,
})
export class AppComponent {
  // signal inputs/outputs, zoneless-safe, no [snapshotService] binding needed
  private capture = injectSnapshotCapture();

  items: NavItem<Report>[] = [
    { id: 'sales', label: 'Sales', icon: '📈', editable: true, data: { owner: 'me' } },
  ];

  // the whole item arrives — no lookup by id
  onSelect(item: NavItem<Report>) { /* ... */ }
  onEdit(item: NavItem<Report>) { /* ... */ }

  // ticks, waits a frame, re-checks the element; resolves null instead of throwing
  save(el: HTMLElement, id: string) {
    return this.capture(el, id, { variant: this.theme() });
  }
}

The Angular package re-exports the core surface (NavItem, SnapshotService, CachedSnapshotStorage, …), so a consumer imports from one package. Peer requirement: @angular/core >= 19.

Capturing safely around navigation

Capture the frame the user is about to leave, not the one that's already gone: flush pending renders, wait one animation frame, then check the element is still attached. That whole dance is injectSnapshotCapture(). Do not wait on whenStable() inside a canDeactivate guard — the router holds a pending task for the entire navigation, so it resolves only after the view is destroyed, and html2canvas then fails with "Unable to find element in cloned iframe". A detached element rejects with SnapshotDetachedElementError rather than storing a blank thumbnail over a good one.

Capturing from a canDeactivate guard, un-awaited

Firing the capture without awaiting it keeps navigation from feeling gated on a thumbnail — but then the router can destroy the view mid-capture. injectDetachedCapture() clones the element first, so that race can't lose: 

import { injectDetachedCapture } from '@anton-gustafsson/snapshot-angular';
import type { CanDeactivateFn } from '@angular/router';

export const reportSnapshotGuard: CanDeactivateFn<ReportPage> = (component) => {
  const capture = injectDetachedCapture();
  void component.captureSnapshot(capture); // not awaited — navigation isn't gated on it
  return true;
};

Scoping the service (lazy routes)

provideSnapshot() returns EnvironmentProviders — it only works at an environment injector location: bootstrapApplication()'s providers, or a route's own providers array. Not a @Component's providers — that's an element injector, and Angular rejects makeEnvironmentProviders() there.

Put it on a lazy route instead of the app root when a feature's snapshots (and its keyPrefix) should live and die with that feature, not with the whole app: 

// app.routes.ts
import { Routes } from '@angular/router';
import { provideSnapshot, CachedSnapshotStorage } from '@anton-gustafsson/snapshot-angular';

export const routes: Routes = [
  {
    path: 'reports',
    loadComponent: () => import('./reports/reports.component').then((m) => m.ReportsComponent),
    providers: [
      provideSnapshot({
        keyPrefix: 'reports:',
        storage: new CachedSnapshotStorage({ /* ... */ }),
      }),
    ],
  },
];

Created once, the first time the route loads. Destroyed — releasing the BroadcastChannel and freeing the keyPrefix claim — when the route's injector is destroyed (deactivated, and RouteReuseStrategy isn't keeping it alive), so re-entering the route later constructs a fresh instance with no "keyPrefix already in use" warning. Skip provideSnapshot() entirely and SNAPSHOT_SERVICE falls back to the app-wide default (providedIn: 'root') — fine for a single feature, but without the keyPrefix isolation and per-feature encode/storage a lazy scope buys you.
